CLI & server · Guida 04

Codex CLI su Mac e server via SSH.

Installa il client, scegli dove vivono repository e strumenti, autentica una macchina headless e verifica il primo lavoro senza confondere “server tuo” con “modello self-hosted”.

Stato della guidaLe istruzioni di installazione e autenticazione sono state confrontate con la documentazione ufficiale OpenAI il 17 agosto 2026. Il flusso completo non è ancora stato provato su uno specifico server di produzione: prima di pubblicarlo come procedura definitiva, va ripetuto su una macchina bersaglio pulita.

Prima: che cosa gira dove?

Codex CLI lavora nella directory e con gli strumenti della macchina su cui lo esegui. Se accedi a un server Linux via SSH e avvii lì codex, repository, shell e comandi sono sul server. Quando usi i modelli OpenAI, il modello resta un servizio esterno.

MacBook Pro └── SSH ──> server Linux sotto il tuo controllo ├── Codex CLI ├── repository e file └── tool locali Codex CLI ── connessione autenticata ──> servizio del modello OpenAI

Questa guida quindi non crea un “Codex self-hosted”. Porta il contesto di esecuzione sul server che controlli.

Prerequisiti

  • Un Mac con terminale e accesso amministrativo al proprio account.
  • Un server Linux raggiungibile via SSH, se vuoi lavorare in remoto.
  • Git installato e un repository di prova senza dati sensibili.
  • Uscita HTTPS dal server verso i servizi necessari.
  • Accesso ChatGPT abilitato per Codex oppure una API key con fatturazione separata.
  • Un checkpoint Git o una copia prima di consentire modifiche.

Registra l’ambiente prima di cambiare qualcosa:

uname -a
git --version
ssh -V

Su macOS puoi aggiungere anche:

sw_vers -productVersion
uname -m

Installa e verifica Codex CLI

La documentazione ufficiale propone lo stesso installer standalone per macOS e Linux:

curl -fsSL https://chatgpt.com/codex/install.sh | sh
Prima di eseguire una pipe verso la shellUsa solo l’URL ufficiale, verifica di essere nel terminale e account corretti e, in un ambiente aziendale, applica la procedura interna di revisione degli installer.

Chiudi e riapri il terminale se l’installer modifica il PATH, poi verifica:

command -v codex
codex --version

Su un Mac con browser, avvia codex dentro una directory di progetto e completa l’accesso proposto. Per controllare lo stato in seguito:

codex login status

Esegui Codex sul server via SSH

Collegati al server e ripeti l’installazione lì: la CLI deve esistere sulla macchina che ospita repository e tool.

ssh user@server.example
cd ~/code/progetto-di-prova
git status
codex --version

Login consigliato su una macchina headless

OpenAI indica il device-code come percorso preferito quando il callback del browser non è disponibile:

codex login --device-auth

Apri sul Mac il link mostrato, accedi e inserisci il codice monouso. L’opzione deve essere consentita nelle impostazioni di sicurezza dell’account o del workspace.

Alternativa con API key

Per workflow locali o programmatici, Codex CLI accetta anche una API key via standard input:

printenv OPENAI_API_KEY | codex login --with-api-key

Non incollare la chiave nel repository, negli script versionati o nella cronologia della shell. L’uso con API key segue fatturazione e policy dell’organizzazione API, non i crediti inclusi nel piano ChatGPT.

Esegui un primo test a impatto minimo

  1. Apri un repository di prova pulito.
  2. Esegui git status e salva l’output.
  3. Avvia codex.
  4. Usa /status per controllare directory e configurazione.
  5. Chiedi: “Spiegami la struttura di questo repository senza modificare file”.
  6. Controlla che nessun file sia cambiato con un nuovo git status.
  7. Solo dopo prova una modifica piccola e reversibile su un branch dedicato.

Criterio di riuscita: la CLI vede soltanto il progetto previsto, descrive correttamente i file e non modifica nulla durante il test di sola lettura.

Permessi e continuità

  • Non usare come primo test un server di produzione.
  • Evita account SSH condivisi e privilegi amministrativi permanenti.
  • Concedi accesso soltanto alle directory necessarie.
  • Conserva log e checkpoint Git prima delle modifiche.
  • Per sessioni lunghe, usa gli strumenti di continuità già approvati sul server; non installare un nuovo demone soltanto per la guida.
  • Non esporre Codex in ambienti pubblici o non attendibili.

Rollback

Se l’esperimento non deve continuare:

  1. Esci da Codex.
  2. Esegui codex logout sulla macchina remota.
  3. Controlla git status e ripristina soltanto i cambiamenti del test con la procedura Git concordata.
  4. Revoca la API key se è stata usata e non serve più.
  5. Identifica il binario con command -v codex prima di pianificare la rimozione; non cancellare percorsi alla cieca.
